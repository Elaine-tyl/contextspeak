# Immersive Unity UI

The game still uses Unity 6, URP and UI Toolkit. Gameplay, speech assessment and persistence remain in the existing C# systems. No Three.js or replacement UI framework was added to Unity.

## Implemented

- Shared 1920×1080 PanelSettings, screen-safe insets and a warm theme for buttons, text fields, dropdowns, toggles, sliders, scrollbars and tabs. Source Sans 3 / Source Serif 4 and an explicit bundled Noto CJK fallback carry their OFL notices in `Assets/Resources/UI`.
- Forest Café: small clock/weather/day chip, one objective, round camera-rendered minimap, contextual needs and projected object prompts. Key hints appear on the first three availability encounters in the current session.
- Phone apps: Map, Quests, Messages, Wallet, Bag, Friends, Settings and Life stories. Map tabs separate the real area map, speaking practice and life scenes. Existing destinations and task commands are retained.
- `M` opens Map, `J` opens Journal, `Tab` opens Bag. Back returns through the phone hierarchy; Home returns to the app launcher. `Esc` opens Settings from the world. Manual input and queued walking routes pause behind the phone.
- Bottom subtitles with subtle letterbox bars; a separate compact feedback/corrected-sentence card and repeat microphone action. Typing remains rehearsal. Wrong repeats and changed quantities cannot advance; spoken order/payment commits are idempotent.
- Paper order panel with context wallet balances and voice controls. Closing the menu exposes the normal dialogue/feedback. No extra confirmation is required to get feedback after recording.
- UI scale, subtitle size, minimal/full/off HUD, reduced motion and colour-safe accent options persist separately from game saves. Major café overlays fade over 180 ms; reduced motion skips the fade.
- Pooled interaction label, map pins and bounded toast queue with at most two visible toasts. The small map/backdrop render targets are reused and refreshed at 2 Hz. Phone glass supports a GPU-blurred world render, with a readable tint fallback.
- Old life, airport, commerce, beach, zoo and city presenters use retained Toolkit controls rather than runtime `OnGUI`. Their existing commands remain authoritative. Modal ownership prevents Settings from unlocking an underlying menu or closing two layers on one Escape press.
- Browser template keeps the character/microphone bridge, while hiding duplicate DOM gameplay overlays when native presentation owns the mode.

## Mocked or incomplete presentation

- The phone is currently a screen-space smartphone interface. A rigged handheld prop/raised-hand animation is not implemented.
- The map is an actual overhead render; its line points directly to the next destination. It is not a calculated street/navigation path. The original café district uses a fixed area map rather than a player-centred zooming minimap.
- Ordering uses the paper UI. Bespoke readable world menu boards and a card-terminal/cash-tray camera close-up still require authored scene/prop work.
- Screenshot dialogue/feedback fixtures use authored sample data and issue no gameplay commands or provider calls. They prove layout, not a real microphone or AI response. Live HUD screenshots use the existing saved scene. Captured world art, characters and lighting are not redesigned by this UI task.
- Legacy location presenters share the theme and modal infrastructure but retain some of their previous screen geometry. Required payment/forms still consume Back without abandoning the transaction.

## Still untested

Actual gamepad navigation, a fresh human microphone session, newly packaged macOS player, every legacy location's visual layout, high UI-scale combinations, and GPU/GC profiling on target hardware. This is not a zero-allocation certification or a claim of complete visual acceptance across all districts. Some saved scenes still contain pre-existing missing-script warnings; importing this UI does not resolve those unrelated scene bindings.

## Voice-only café dialogue and grounding

The ForestSlice conversation no longer contains a typed-reply field or its Enter handler. Microphone recording, replay, correction and spoken task gates remain; settings fields still accept text. The glossary/history/close controls use `Aa`, `Log` and `×`, with descriptive tooltips and readable selected states. Offline messages direct the learner to reconnect voice rather than suggesting a removed input.

`ContextSpeak > Environment > Repair saved café grounding` backs up ForestSlice, ForestCafe and LifeTown before adjusting whole imported models, grouped furniture and actor roots. It uses visible/baked geometry and supporting floor colliders. Plants can use a table or planter as support. Suspended decorations, boats, separately authored canopies and individual procedural tabletops/cushions retain their authored positions. LOD metadata alone does not classify an object as a grounded tree. Unclassified assets remain untouched; this is not a blanket certification of every district or supplied FBX.

The accepted repair adjusted 527 model roots (504 in ForestSlice, 16 in ForestCafe and 7 in LifeTown). Original scenes and the per-object change report are retained in `.local/grounding/applied-20261114.074029/`. The first broad repair passes were restored before the accepted repair was applied.

`ContextSpeak > Checks > Voice controls and grounded props` runs 14 native fixtures: whole furniture/NPC/tree grounding, elevated supports, pots, preservation of decorations and procedural furniture parts, repeat-repair stability, removal of typed dialogue input, compact labelled tools and retention of microphone controls. The source/bridge checks do not replace a live microphone session or visual inspection.
