# ContextSpeak Life Town Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Play a linked spoken-English day across home, market and cafe.

**Architecture:** A shared authored catalog and pure C# state machine own goals,
inventory and payments. A local bounded review adapter supplies language feedback;
Unity gameplay, native UI and semantic browser UI consume the same mission state.

**Tech Stack:** Existing Unity 6000.6.8f1, URP17.6.0, C#, TypeScript/Zod, local
Whisper/Qwen/Phonon, Vitest and Playwright; no new runtime dependencies.

**Spec:** `docs/superpowers/specs/2026-11-11-life-town-design.md`

## Global Constraints

- Preserve the existing ForestCafe, Godot games and account/extension behavior.
- English product UI; integer cents; $20 start; $7 groceries; existing cafe prices.
- Voice earns steps; typed replies rehearse; practice never overwrites earned saves.
- Corrected wording requires a new recorded answer, with equivalent meaning allowed.
- Plain text only; exact loopback origin/session guards; no cloud keys in clients.
- No commits/pushes without a new user request; preserve existing uncommitted work.

## Review Focus

- A late microphone/model response after closing or changing stage must do nothing.
- Negated quantities, ambiguous confirmation and model-invented drink choices cannot buy items.
- Typed rehearsal and repeated delivery/payment callbacks cannot earn rewards.
- Malformed/version-mismatched saves cannot restore impossible steps or negative money.
- NPCs must remain reachable and UI/keyboard ownership must work on both targets.
