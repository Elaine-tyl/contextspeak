# Unity game unification

Approved direction: Unity 6 LTS, C#, URP and server-side/local-companion AI for
all game clients. The TypeScript website and extension continue to own login,
vocabulary, learning history and trusted scoring. This supersedes the earlier
Unity/Godot split. No RAG or new database is required for the local Life world.

## Deliverable

Use one project, `games/unity`, with `_Game` runtime folders, Editor builders,
verified CC0 art and reproducible generated scenes. Preserve the cafe mission,
Life first day, automatic recording assessment, correction/repeat gate, local
saves and practice/earned separation. Move the eight account-connected arcade
modes from Godot to a Unity UI Toolkit board with the same ten-level catalog,
server scoring, microphone host, run restoration and accessible web fallback.

Install the official 6000.3.28f1 LTS Editor alongside 6.6; do not downgrade a 6.6
Library in place. Keep the current exports until their replacements pass.
Pin compatible packages, use Input System for controls, Cinemachine for camera
composition, NavMesh for world navigation, Animator for NPC interaction states,
and data assets for reusable NPC capabilities/quests. Build only useful shared
systems; no placeholder managers for future districts.

The Unity client records and presents feedback; it never embeds API keys or
claims a transcript is an acoustic pronunciation score. Scene changes and closing
conversations cancel work and reject stale callbacks. A failed load preserves a
usable scene. Guest Life saves and account arcade results remain separate.

## Expansion boundary

Home, market and cafe remain the first playable loop. School, farming, clothing,
restaurants, fishing, entertainment, civic services and international travel are
subsequent content releases on the shared framework. They must be labelled as
planned until playable. Addressables/additive loading should serve real scenes;
do not add empty district scenes to imply completion. The desktop guest world
works with the local AI companion. Native account-connected arcade login is a
separate future pairing feature; no extension credentials are reused.

## Safety and reproducibility

Archive legacy engine source locally before retiring active Godot launch paths;
retain shared questions, licenses and art provenance. Existing save keys and
progress semantics remain compatible. Generated exports/caches are ignored.
Never silently accept installer legal terms. Keep code commented where cancellation,
trust boundaries or engine lifecycle make the reason non-obvious.
